## Checked and clean
1. **Secrets and identifying information** — swept code, comments, string literals, README prose, example config, and LICENSE for credentials, tokens, PEM blocks, hostnames, personal domains, IPs (RFC 1918/loopback/CGNAT), secret-store paths, local filesystem paths, and control characters/NULs (grep-verified clean): nothing found beyond the deliberate public identity items in findings 6 (`jpisgeek`, `slog-bog` repo URLs are the published vendor namespace; "Example AI" placeholder is obviously fake).
2. **Credential handling** — no argument carries a secret, so no `sensitive` marking is required; no logging anywhere; no secret can reach errors, resource attributes, or filenames; URL userinfo is rejected at the writer (finding 1/2 cover the scheme and reader-side gaps).
3. **Transport and network** — the extension performs zero network calls (verified: no fetch, no timeouts needed, no TLS options exist to disable); the only URL handling gap is finding 1.
4. **Untrusted input** — writer schema is `.strict()`; absent snapshot yields state `unknown` with an info exception, never "healthy"; no shell/SQL/SSH/file-path construction; static resource and section IDs cannot collide; `declared-limit-<index>` IDs are unique; no `.passthrough()` on operator input (contract-side passthroughs are the platform's versioning mechanism); see findings 2–4.
5. **Supply chain** — the only import in both published sources is `npm:zod@4` (the sanctioned platform specifier); no other dependencies, no dynamic `import()`, no `eval`/`new Function`, nothing fetched at load time.
6. **Documentation matches code** — method count (1: `capture`, no args), resource name/lifetime (`snapshot`, 365d), field list, version strings (manifest = README = model = producer, all `2026.08.25.1`), rejection of remaining-quota/per-token limit names, and the example config all verified against code; see finding 5 for the constraint-documentation drift.
7. **Data written** — see below; commercially sensitive nature is disclosed in the README Security section; no field can carry a secret given the writer's `ReferenceSchema` (finding 2 notes the provenance-copy exception).
