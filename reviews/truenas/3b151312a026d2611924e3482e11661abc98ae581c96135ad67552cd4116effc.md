## Checked and clean
1. **Secrets & identifying info** — swept all string literals, comments, schema descriptions, README prose, and examples. All hosts/domains are documented placeholders (`nas.example.com`, `truenas.example.com`); vault reference is generic (`'myvault'`, `<your-truenas-api-key-item>`); no credentials, IPs, local filesystem paths, serials, or private model/workflow names; the one control character (U+001F) is written as an escape sequence, not a raw byte. LICENSE name: see finding 4. The `.swamp/pulled-extensions/@swamp/ssh/...` comment path references a public extension, not the operator's environment.
2. **Credential handling** — `apiKey` carries `.meta({ sensitive: true })` (truenas.ts:44); the RPC error path deliberately drops the middlewared `data` traceback that could echo the key (auth call takes the key as its only argument) and surfaces only code + message; timeout/abort/close errors name only the method or the wsUrl; userinfo in `baseUrl` is rejected before the URL can reach logs; nothing writes the key to disk or resources. Clean.
3. **Transport & network** — HTTPS/WSS required by default with no way to disable TLS verification; cleartext opt-out reported as finding 1. `assertBaseUrl` restricts schemes to http/https (no `file://`/`data:` possible); vendor-domain pinning is N/A (the endpoint is the user's own NAS by design). Connect and every RPC call carry timeouts; `AbortSignal` is honoured on connect and per-call, and abort is reported as "aborted", not as a timeout or remote failure. Clean apart from finding 1.
4. **Untrusted input** — see findings 2 and 3. No HTML rendering, no shell/SQL/file-path construction from API data. Failure is not disguised as health: non-array results throw before any write or prune, all five queries run in one `Promise.all` so a partial failure aborts the whole pass, null `healthy` counts as unhealthy, null `dismissed` counts as active, and missing cert expiry is flagged via `expiryKnown` rather than a fake day count.
5. **Supply chain** — exactly one import, `npm:zod@4`, which is the sanctioned platform exception (runtime-provided zod). No other dependencies, no dynamic `import()`, no `eval`/`new Function`, nothing fetched at load time. Clean.
6. **Docs match code** — README argument table matches `GlobalArgsSchema` (names, types, required, defaults 20/30/false); one method `discover` with no arguments matches; all six resource tables match the zod schemas field-for-field including `summary`'s twelve fields; version string matches manifest and `model.version`; Security and Caveats prose match actual behaviour (userinfo rejection, TrueNAS 27 warning, silenced-alert semantics). Clean.
7. **Data written** — inventoried below; personal/identifying fields are disclosed in the README's Security section ("hostname, version, pool names and health, disk models and serial numbers, alert text, certificate names and CNs"). No write path can contain the API key. Clean.

## Data written by this extension
- `system` — NAS hostname (identifying), hardware model, CPU/memory/uptime/load.
- `pool` — ZFS pool names, health, capacity, fragmentation.
- `disk` — device names, **hardware serial numbers** (identifying, warranty-traceable), models, sizes, pool membership.
- `alert` — full formatted alert text (may embed hostnames, dataset names, or usernames present in TrueNAS's own alert prose), class, level, dismissed/silenced state.
- `certificate` — certificate names and common names (may reveal internal DNS names), expiry dates and derived flags.
- `summary` — hostname plus aggregate counts and sync timestamp.
