## Checked and clean
1. Secrets and identifying information — grepped all four files for credentials, PEM/token/key material, emails, hostnames, IPs (all forms), secret-store paths, local filesystem paths, and control characters: none. All examples are placeholders (`<id from ...>`, `host.example.net`, `unreachable:printer`); defaults are relative paths. Only identity items are the deliberate LICENSE name (finding 7) and the public repo/handle URLs.
2. Credential handling — the extension takes no credentials, uses no vault, and no secret can transit its log lines, error paths, resources, or the HTML; catch blocks log only source name/type/model-id and the error message. Clean.
3. Transport and network — no network code exists at all (verified: only `Deno.mkdir`/`Deno.writeTextFile` and `ctx.dataRepository`/`ctx.writeResource`/`ctx.deleteResource`); no TLS options, no URLs fetched, README's "reaches no network" claim matches the code. Clean.
4. Untrusted input — every HTML interpolation of source-derived data goes through `esc()` (attribute-position values are internal literals or `Number()` results); no shell/SQL/path construction from data; missing `exitCode` correctly reads as "unknown" not "healthy"; resource naming is slug+FNV-1a keyed on raw id. Remaining gaps are findings 1–5.
5. Supply chain — single import `npm:zod@4`, which is the sanctioned runtime-provided specifier; no other imports, no dynamic `import()`, no `eval`/`new Function`, `dependencies: []` in the manifest. Clean.
6. Documentation matches code — README arguments table, defaults, single `render` method, resource names/fields/lifetimes, instance-name behavior, the four literal aliases, the `known-source-aliases` check, and the example config all match `dashboard.ts` and `manifest.yaml`; versions agree everywhere (`2026.08.22.2`). Clean apart from the stderr disclosure gap (finding 6).
7. Data written — enumerated below; the README Security section discloses that the page carries machine names, addresses, mounts, and certificate names and advises auth. See findings 6 (stderr) for the one disclosure gap.

## Data written by this extension
- `exception` resources (one per detected exception, suppressed included): exception id, severity, host/node names as `subject`, alarm/cert headlines, detail text that can include mount paths, certificate common names, TrueNAS alert text, and the last line of SSH probe stderr; tags carry severity/subject/suppressed.
- `render` resource: output path, byte count, exception/suppression/severity counts, sources read, stale-source names, timestamp. No personal data beyond the configured source aliases.
- HTML file at `outputPath` (local disk, delivery out of scope): machine names, primary IP addresses, network names, device types, online state (Firewalla), node names/OS/versions, mounts and usage, certificate names/common names/expiry — personal infrastructure inventory; README warns to keep it behind authentication.
