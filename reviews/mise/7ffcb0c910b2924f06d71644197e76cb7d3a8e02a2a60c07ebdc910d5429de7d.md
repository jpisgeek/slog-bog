## Checked and clean
1. Secrets/identifying: scanned all four files' code, comments, string literals, README prose, and examples; grep sweeps over the published files found zero credentials, tokens, PEM blocks, private/public IPs, personal domains, local filesystem paths, secret-store item names, and zero control characters; only domains present are `example.com` and the vendor's own public GitHub repo; examples use role words and `/srv/project` — clean except findings 2 and 5.
2. Credential handling: the extension takes no secret arguments and reads no vault (`vaults: []`); error text embeds stderr only, truncated to 160 chars, never stdout (mise/mise.ts:365–373, 381–388); no URL userinfo anywhere; nothing persists a secret — clean.
3. Transport/network: no HTTP at all, so no cleartext opt-out and no TLS to misconfigure; SSH runs the system client with `BatchMode=yes` (unknown host key fails closed, mise/mise.ts:241–243) and host-key checking is never weakened; every spawn carries `AbortSignal.timeout` plus a capped `ConnectTimeout`; caller cancellation is rethrown, never misfiled as a host failure (mise/mise.ts:362–364, 378) — clean.
4. Untrusted input: remote JSON is top-level shape-checked before the tolerant parsers run (mise/mise.ts:440–457); failed or unparseable probes become `unmeasured`/`degraded` with null counts, never zeros; no HTML rendering; operator strings reaching the remote command are charset-refused at parse time and local invocations are argv arrays with no shell; resource identity is length-prefixed truncated SHA-256, immune to slug-collapse collisions — see findings 1 and 3 for the surviving edges.
5. Supply chain: the sole import is `npm:zod@4` at mise/mise.ts:20 (the sanctioned runtime-provided bare major); `dependencies: []`; no eval, `new Function`, dynamic `import()`, or load-time fetch — clean.
6. Docs vs code: argument names, types, and defaults, the single `discover` method, all four resource field lists, the five subcommands, the quoting/refusal description, the BatchMode claim, the hash-suffix naming caveat, and the example config all verified against source — clean except findings 1 and 4.
7. Data written: enumerated below; the README Security section discloses that install and config paths embed home directories and real project names and says to treat the datastore as infrastructure detail — clean.

## Data written by this extension
- `node` — operator-chosen host label, transport, the measured directory path, mise version, counts, drift classes, and on failure a stderr snippet (which over SSH can include remote banner text).
- `tool` — tool names and versions per host, plus `installPath`/`sourcePath`, which embed the remote account's home directory and project directory names (personal/infrastructure detail; disclosed in the README).
- `config` — mise config file paths (home and project directories; disclosed), declared tools, trust state.
- `summary` — fleet counts and an ISO timestamp; no personal data.
- No credentials, no user lists, no MAC addresses, and no secret can reach any of these fields; the only sensitive content is path-shaped infrastructure detail, which the README warns about.
