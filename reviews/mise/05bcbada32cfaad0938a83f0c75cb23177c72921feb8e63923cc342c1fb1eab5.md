## Checked and clean
1. **Secrets and identifying information** — searched all four files for credentials, keys, PEM blocks, tokens, real hostnames, IPs (all forms), personal domains, secret-store paths, local filesystem paths, and control characters in string literals: none present. All examples are properly fake (`builder.example.com`, `/srv/project`, `toolchain-reader`, `{node: '22'}`). The only public identifiers are the intentional `@jpisgeek`/`github.com/jpisgeek/slog-bog` publishing identity and the LICENSE name — see finding #2.
2. **Credential handling** — no argument carries a secret, so nothing requires a sensitive marker; SSH authentication is delegated entirely to the ambient key agent (`BatchMode=yes` forbids password prompts, mise.ts:243). Error paths quote stderr only, never stdout (mise.ts:370; the unparseable case uses a fixed string, mise.ts:875); nothing writes a secret to disk, logs, resources, or names.
3. **Transport and network** — no HTTP/WS anywhere; the only transports are local exec (argv, no shell) and the system `ssh` binary. Unknown host keys fail closed under BatchMode; no TLS-disable or cleartext option exists. Every subcommand carries `AbortSignal.any([caller, timeout])` on both branches (mise.ts:336–339, 346–349); caller cancellation is re-thrown, never recorded as a host failure (mise.ts:362–364, 378, 1023), and no writes occur on a cancelled run (choke point at mise.ts:1066).
4. **Untrusted input** — remote JSON is shape-checked before tolerant parsing (`isJsonPayload`, mise.ts:440), fields are individually type-guarded, and prototype-chain lookups are blocked by null-prototype maps plus `Object.hasOwn` (mise.ts:539, 556, 946, 952, 978). Shell surfaces verified: `dir`/`misePath` charset schemas exclude every metacharacter including newline (JS `^...$` without `m` cannot span one), `..` segments refused (mise.ts:58, 76); `ssh.host`/`ssh.user` occupy one argv element with leading-dash refusal, and I confirmed no option-injection or destination-rewriting path through `user@host` (mise.ts:248). Resource identity uses length-prefixed parts under truncated SHA-256 (mise.ts:695–717) — collision requires a second preimage. Failure is never disguised as health: unmeasured hosts get null counts, degraded hosts are flagged on node, summary, tags, and error fields. Residual: control characters, finding #1.
5. **Supply chain** — exactly one import, `npm:zod@4` (mise.ts:20), which is the sanctioned bare-major form for zod on this platform; `dependencies: []` matches; no `eval`, `new Function`, dynamic `import()`, or fetched code; everything else is a runtime global (`Deno.Command`, `crypto.subtle`).
6. **Documentation matches code** — verified type name, version, the single `discover` method and its `node` argument, every argument name and default (port 22, timeoutSec 15, maxConcurrency 8, misePath "mise", expect {}), all four resource field lists against the zod schemas field-for-field, the five subcommands against `SUB_*`, the quoting claims against `remoteCommand`/`sshArgs`, prune/summary/single-node semantics against `execute`, and the example config against the schemas (all values pass). No drift found.
7. **Data written** — enumerated below; paths embed remote home directories and project names, and the README Security section explicitly discloses this ("treat the datastore as infrastructure detail"). No write can contain a secret; stdout (which carries config contents) is excluded from every written field.

## Data written by this extension
- `node` — host label, transport, measured/degraded state, failure kind, the measured directory (operator-set path or the local working directory — infrastructure detail), mise version, drift classes, and an error field quoting up to 160 characters of remote stderr.
- `tool` — per host: tool name, requested/resolved/latest versions, install path (embeds the remote account's home directory), config source path, installed/active/outdated flags, drift classes.
- `config` — per host: mise config file path (embeds home and project directory names), trust state, declared/in-effect/not-in-effect tool lists.
- `summary` — fleet-wide counts and sweep timestamp only; no per-host detail.
- No credentials, tokens, or config file contents are ever written; the identifying material is limited to hostnames-as-labels and filesystem paths, and the README tells the user to treat the datastore accordingly.
