## Checked and clean
1. **Secrets & identifying info**: swept all four files — code, comments, describe strings, README prose, example config — for credentials, keys, tokens, PEM blocks, hostnames, IPs, secret-store paths, and local filesystem paths; found none. Only non-vendor identifiers are the deliberate public repo `github.com/jpisgeek/slog-bog` (README.md:43, manifest.yaml:13) and the LICENSE name (finding 1). All placeholders are properly fake: `builder.example.com`, `toolchain-reader`, `/srv/project` (README.md:97-116). Byte-level grep of the on-disk files (verified byte-identical to the delimited input) found no control characters or NUL bytes.
2. **Credential handling**: the extension defines no secret-carrying argument and declares no vaults (manifest.yaml:19), so nothing requires a sensitive marker; errors quote only a 160-char printable stderr excerpt, never stdout (mise/mise.ts:347-418); no URLs exist anywhere, so no userinfo path; nothing is persisted to disk — clean.
3. **Transport & network**: the only network transport is SSH; `BatchMode=yes` fails closed on unknown host keys and there is no option to weaken host-key checking (mise/mise.ts:264-279); no cleartext opt-out exists; every spawn carries `AbortSignal.any([caller, timeout])` (mise/mise.ts:364-378) plus a capped `ConnectTimeout`, and caller cancellation is rethrown, never misreported as a host failure (mise/mise.ts:386-407, 1049-1054) — clean.
4. **Untrusted input**: no HTML is rendered; remote command text is confined by schema charset refusal (`SAFE_ABS_PATH`/`SAFE_BIN_PATH`, mise/mise.ts:27-29) plus argv-only local execution (mise/mise.ts:235-239) and single-quoted `dir` (mise/mise.ts:247-256); remote strings are made printable before reaching data, tags, or logs (mise/mise.ts:37-46); remote-controlled keys are looked up via `Object.hasOwn` on prototype-free maps (mise/mise.ts:569,586,976-982); resource identity uses length-prefixed truncated SHA-256, immune to separator collisions (mise/mise.ts:707-747); failure is recorded as unmeasured/degraded with null counts, never as zero — see findings 2-4 for the residual notes.
5. **Supply chain**: exactly one import, `npm:zod@4` (mise/mise.ts:20), which is the sanctioned bare-major zod specifier; `dependencies: []` (manifest.yaml:31); no dynamic `import()`, no `eval`, no `new Function`, nothing fetched or executed at load time — clean.
6. **Docs match code**: README argument table, defaults (`22`, `15`, `8`, `"mise"`, `{}`), the single `discover` method and its one optional `node` argument, all four resources' field lists and infinite lifetimes, prune/single-node/summary behaviour, hash-suffixed names, `expect` segment matching, `failureKind` values, and every Security-section claim (subcommand allowlist, argv vs quoted interpolation, leading-dash rule, printable escaping, BatchMode, stderr-only errors) were checked against the source line by line; the example config parses under the published schema — clean.
7. **Data written**: enumerated below; the README explicitly warns that install and config paths embed home directories and real project names and says to treat the datastore as infrastructure detail (README.md:153-156) — see findings.

## Data written by this extension
- `node` — operator-chosen host label, transport, failure kind, a bounded printable stderr excerpt (`error`), mise version, the measured directory path (operator infrastructure detail), counts, drift.
- `tool` — tool names and versions, `installPath` and `sourcePath`: these can embed the remote account's home directory (a real username) and real project directory names — personal/identifying, and disclosed to the user at README.md:153-156.

- `summary` — fleet aggregate counts and a sweep timestamp; nothing personal.
