## Checked and clean
1. Secrets and identifying information: searched all four published files for credentials, tokens, keys, PEM blocks, real hostnames, domains, subdomains, IP addresses, MAC addresses, emails, secret-store paths, local filesystem paths, and control characters in literals — none found. Examples use `example.com`, `/srv/project`, `toolchain-reader`, and role-word node names; source-comment examples ("nas-01"/"nas") are category words, not fleet machines. The only identifying content is deliberate author attribution — see finding 4.
2. Credential handling: the extension accepts no secret-carrying argument (SSH auth is ambient key/agent; manifest `vaults: []`), so there is nothing to mark sensitive; errors quote stderr only, capped at 160 chars; stdout (which carries config contents) never reaches errors, logs, or thrown messages, including on every catch path; no URL userinfo exists; nothing persists a secret — clean.
3. Transport and network: SSH-only, no HTTP surface, no cleartext opt-out exists; `BatchMode=yes` makes unknown host keys and password prompts fail closed and no option weakens host-key verification; every spawn carries `AbortSignal.timeout((timeoutSec+10)*1000)` plus a 10s-capped `ConnectTimeout`; the caller's `AbortSignal` is honoured and cancellation is rethrown, never classified as a host failure (verified in `runMise` and the worker catch) — clean.
4. Untrusted input: remote JSON is shape-checked (`isJsonPayload`) before the tolerant parsers see it, so garbage cannot evaporate into a clean-looking empty result; prototype-chain lookups on remote-controlled keys are guarded with `Object.hasOwn` (expect, outdated, trust); unmeasured hosts keep null counts and degraded hosts name their failed subcommands, on rows as well as nodes, so failure is never disguised as health; local exec is argv-only, and remote interpolation of `dir`/`misePath` is protected by charset refusal at parse time with `ssh.host`/`ssh.user` as single argv elements refusing a leading dash; identity naming is length-prefix-hashed — residuals in findings 2 and 3.
5. Supply chain: the sole import is `npm:zod@4`, the sanctioned bare-major specifier for the runtime-provided zod; `dependencies: []`; no other npm/jsr/https imports, no dynamic `import()`, no `eval`/`new Function`, nothing fetched at load time — clean.
6. Documentation matches code: verified type name, version string (manifest, README, `model.version`), the single `discover` method and its `node` argument, the full arguments table including defaults, all four resource field lists against their zod schemas, lifetimes, the five-subcommand list, the quoting/argv description in the Security section, prune and single-node/degraded-host retention behaviour, `failureKind` values, and the example config against the schemas — one drift, see finding 1.
7. Data written: reviewed all four resources; the personal-data exposure (home directories, project directory names, host labels) is explicitly disclosed in the README Security section ("treat the datastore as infrastructure detail") — see below.

## Data written by this extension
