## Checked and clean
1. Secrets and identifying information: reviewed all six published files; no credential literal, private operator path/host/account, control character, or hidden secret was found. Public publisher/repository/vendor identity and obviously synthetic examples are accepted.
2. Credential handling: API tokens are sensitive, sent only in Authorization headers, excluded from URLs/resources/tags, and redacted and echo-checked across response and error paths before storage or logging. Probe input is also sensitive and screened from errors. See finding 1 for transport exposure.
3. Transport and network: URLs reject userinfo/query/fragment and non-HTTP schemes, redirects are refused, response bodies are capped, request deadlines exist, and caller cancellation remains distinct from timeout or endpoint failure. Remote daemon mode restricts the cleartext CLI connection to a loopback address for an encrypted tunnel. See finding 1.
4. Untrusted input: endpoint responses and CLI output are bounded, screened, and schema-validated; missing measurements remain unknown rather than zero; model identifiers are bounded and screened; deterministic length-prefixed identities avoid separator collisions; no response text is rendered as HTML or passed to a shell. The daemon runner override is held only in the current observation context and defaults directly to the immutable production runner, so one call cannot alter a later observation.
5. Supply chain: only sanctioned runtime `npm:zod@4` is imported; no dynamic code, remote dependency, eval, or fetched executable exists. The daemon subprocess uses fixed argv with a cleared environment, bounded output, timeout, cancellation, and descendant-pipe cleanup. The exported test runner is an immutable reference and cannot replace production execution.
6. Documentation matches code: verified all three models, methods, arguments, resource schemas, endpoint and daemon transport rules, response bounds, cancellation, error/unknown semantics, identity rules, per-observation runner isolation and written-data disclosure.
7. Data written: see below. The README identifies endpoint/model/probe/daemon operational data and token-usage sensitivity. No bearer token or prompt/input text is written.
