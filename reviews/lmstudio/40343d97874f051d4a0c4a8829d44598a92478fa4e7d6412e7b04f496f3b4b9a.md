## Checked and clean
1. Secrets/identifying info: searched both source files, README, manifest, and LICENSE for credentials, keys, PEM blocks, hostnames, personal domains, IPs (RFC 1918/CGNAT/ULA/public), vault item paths, local filesystem paths, and control characters — every example is `inference.example.com` / `myvault` / `ExampleService`, the only local path mentioned is the platform's own `.swamp/data/`, and nothing identifies the operator's environment except the LICENSE attribution (finding 6).
2. Credential handling: `apiToken` carries `.meta({ sensitive: true })` in both files; token appears only in the Authorization header; every response body is passed through `redact()` before classification, storage, or throw (including the double-redact on the UNAUTHORIZED throw path); `baseUrl` refine rejects userinfo; `safeUrlForLog` strips userinfo and query from every logged URL; nothing persists the token — clean apart from the exact-match limitation (finding 5).
3. Transport/network: scheme restricted to http/https (no `file://`/`data:`); TLS verification is never touched and no disable option exists; hostname validation is inapplicable by design (user-supplied generic endpoint, no vendor domain); every fetch combines `ctx.signal` with `AbortSignal.timeout` and cancellation is distinguished from timeout via the caller's raw signal, including during the 429/503 backoff wait — cleartext opt-out reported (finding 1), redirect policy noted (finding 4).
4. Untrusted input: no HTML rendering, no shell/SQL/path construction from API data; instance names use a slug plus SHA-256-derived suffix from the un-normalized model id, so distinct ids cannot collide; malformed 2xx bodies, empty vectors, missing choices, and partial capability batteries are all recorded as their own error kinds rather than as health — except the zero-backfilled usage counts (finding 3).
5. Supply chain: sole import is `npm:zod@4`, the sanctioned runtime-provided specifier; no other npm/jsr/https imports, no dynamic import, no eval/new Function, dependencies list empty and matches.
6. Docs match code: verified method names/counts (2 + 3), every argument name/type/default, every resource field list against the zod schemas, instance-name format, throw-vs-record behaviour per method, and both example blocks — one drift found (finding 2).
7. Data written: reviewed all five resource writes and their tags; no personal data, no secrets, caller prompts and completion content are not stored (only lengths and counts), and the README's "Data written" tables and Security section state exactly this.

## Data written by this extension
- `models` — served model ids and a count, plus `syncedAt`. Reveals which models an endpoint serves; no personal data.
- `health` — reachability/authorization booleans, HTTP status, latency, error kind/text. Error text can include the operator's own endpoint hostname (local datastore only, not published).
- `embeddingProbe` — model id, measured vector dimension, `dimensionKnown`, latency, HTTP status, error kind/text. Embedding input text is not stored.
- `completionProbe` — model id, latency, finish_reason, token counts, reasoning/content character counts, heuristic flags, error kind/text. The caller's prompt and the model's reply are not stored.
- `capabilityProbe` — model id, three capability booleans, `checksCompleted`, per-check truncation flags, latency, error kind/text. Battery responses are not stored.
