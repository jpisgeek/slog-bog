## Checked and clean
1. **Secrets/identifying info**: searched all four files' code, comments, string literals, and prose for credentials, PEM blocks, real hostnames, IPs (RFC 1918 or public), MACs, secret-store item paths, local filesystem paths, and control characters in literals — none present; every example value is fake (`example-msp.firewalla.net`, `your-msp-domain.firewalla.net`, `myvault`, `ExampleVault/API Key`, `example-host`); the only real-identity items are the intentional LICENSE/README attribution (finding 7). Control-character check is by inspection of the provided text, not a byte-level grep.
2. **Credential handling**: `token` is `.meta({ sensitive: true })` (firewalla.ts:49); sent only in the `Authorization` header to the validated host; never logged, never written to a resource, never in a URL; userinfo URLs rejected (firewalla.ts:217); 401/403 errors omit the body; other error bodies pass through `redact()` and are truncated to 200 chars — see findings 2 and 4 for the doc drift and the one unredacted parse-error path.
3. **Transport/network**: HTTPS is hard-coded (`https://${domain}`), no cleartext opt-out exists, no TLS-disable option exists; hostname is URL-parsed and checked on `.hostname` against `*.firewalla.net` with path/query/fragment/port/userinfo all rejected, defeating suffix-string tricks; timeout via `AbortSignal.timeout` combined with the caller's signal via `AbortSignal.any`; caller cancellation is reported as `CANCELLED`, not as a remote failure; retry waits are abortable and capped at 5 s — see finding 1 for the missing redirect policy.
4. **Untrusted input**: no HTML rendering, no shell/SQL/SSH command construction anywhere; API fields are individually coerced with explicit sentinels (`(unnamed)`, `(unknown)`, `(unset)`) rather than empty strings, records with no `id` are skipped and logged, and an unrecognised response shape throws; resource names hash the full identity tuple (`gid|mac|id`, FNV-1a) so slug collisions cannot merge records, and same-name distinct machines get a MAC-suffixed key; fetch failures throw rather than writing a healthy-looking empty inventory — findings 3, 5, 6 cover the residual edges.
5. **Supply chain**: the sole import is `npm:zod@4`, the sanctioned runtime-provided specifier; no other npm/jsr/https imports, no dynamic `import()`, no `eval`/`new Function`, no deserialisation into code, manifest `dependencies: []`.
6. **Docs match code**: version string identical in README, manifest, and model; type name, single method, method args and defaults, all ten global arguments with their defaults and descriptions, all three resource field lists, tag lists, prune-on-full-sync-only behaviour, and the Caveats claims verified verbatim against the source — see findings 2 (Token header wording) and 5 (example footgun).
7. **Data written**: personal network inventory (names, MACs, IPs, vendors, traffic totals) is written; the README Security section explicitly warns the user; no write path can contain the token.

## Data written by this extension
- `device` — one per Firewalla-known device, including offline ones: device name, IP, MAC address, MAC vendor, network name, online state, traffic totals. Personal data (network inventory); disclosed in README Security section.
- `machine` — one per deduplicated host: machine name, primary IP, per-NIC name/IP/MAC/network list, dependency edges. Personal data; disclosed.
- `inventory` — roll-up: the operator's MSP domain, device/machine counts by tier and state, network name list, deviceType histogram, sync timestamp. Contains the real MSP domain and network names; disclosed in the README fields table.
- No resource, tag, log line, or file write contains the token or any other secret.
