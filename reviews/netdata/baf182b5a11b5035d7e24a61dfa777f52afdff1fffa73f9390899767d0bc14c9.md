## Checked and clean
1. Secrets and identifying information: reviewed all four published files; no credential literal, real operator infrastructure, local path, account identifier, control character, or hidden secret was found. Public publisher/repository/vendor identity and synthetic examples are accepted.
2. Credential handling: the extension accepts no credential. Node URLs reject userinfo, query strings, and fragments, curl ignores config files and disables proxies, and stored failure text is selected from fixed classes. See finding 2 for intentionally sensitive runtime diagnostics.
3. Transport and network: schemes are restricted to HTTP(S), redirects are refused on direct and SSH transports, HTTPS verification cannot be disabled, SSH forces strict host-key checking, every call has request and whole-node deadlines, and caller cancellation is rethrown rather than stored as node failure. See finding 1.
4. Untrusted input: API envelopes and projected fields are schema-validated; bodies, text fields, node/cardinality fanout, subprocess streams, and whole-node work are capped; missing measurements remain absent; degraded or incomplete nodes preserve old detail instead of reporting false zero/healthy state; normalized-name collisions are rejected and resource identities use length-prefixed wide hashes. The SSH command uses fixed local argv and a single-quoted remote command whose interpolated URL and identity components reject command-breaking characters. Remote log text is control-stripped and bounded. See findings 1 and 2.
5. Supply chain: only sanctioned runtime `npm:zod@4` is imported; no dynamic code, fetched executable, eval, or additional dependency exists. The fixed `ssh` subprocess enforces bounded pipes, deadline/caller cancellation, SIGKILL, and cleanup even when descendants retain descriptors.
6. Documentation matches code: verified the single discovery model, node/SSH configuration, four API calls, concurrency and cardinality bounds, direct/SSH transports, redirect policy, unknown/degraded semantics, deterministic identities, pruning behavior, written fields, and log disclosure. See findings 1 and 2.
7. Data written: see below. The README explicitly classifies it as infrastructure inventory and states that remote free text is persisted after bounding and control-character replacement. No credential is written.
