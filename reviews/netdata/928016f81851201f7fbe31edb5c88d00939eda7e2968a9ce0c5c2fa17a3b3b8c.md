## Checked and clean
1. Secrets/identifying info: searched all four files for credentials, PEM blocks, tokens, real hostnames/domains, RFC 1918/public IPs, secret-store paths, local filesystem paths, and control bytes. All hosts are `example.com`/loopback, the one control character is written as an escape sequence, no vault paths exist (`vaults: []`), no local paths. See findings 6–7 (informational only).
2. Credential handling: the extension accepts no secret arguments at all (SSH auth is delegated to the local ssh key/agent, never passed in). URL userinfo is rejected at the schema. Persisted `error` goes through `sanitizeNodeError`, which strips `user@host`, ssh stderr, and HTTP bodies; raw detail stays in logs. HTTP error bodies are truncated in the thrown message and the persistence regex drops them. Nothing writes a secret to disk or `.swamp/data`. Clean.
3. Transport: TLS verification is never disabled and no option exists to disable it (no `-k` on the remote curl, no Deno TLS overrides). Timeouts exist on every call (fetch `AbortSignal.timeout`, curl `--max-time` + `ConnectTimeout` + outer process timeout); top-level cancellation is rethrown before any write. Vendor-hostname validation is N/A (self-hosted agents). Schemes restricted to http(s); `file:`/`data:` rejected. See findings 1–3.
4. Untrusted input: no HTML rendering. SSH command injection checked closely and is closed: the remote command is a single argv element (no local shell), the URL schema rejects single quotes, the path has quotes stripped (`path.replace(/'/g, "")`) which covers the `encodeURIComponent` gap (it leaves `'` unescaped), and `ssh.host`/`ssh.user` reject leading `-` (option injection). Node-name uniqueness enforced; failure is not disguised as health (carry-forward + `nodesDegraded` + `protectedPrefixes`, and the previous `?? 0` mount-dimension bug is fixed by refusing to guess). See findings 4–5.
5. Supply chain: exactly one import, `npm:zod@4`, which is the sanctioned platform specifier. No other dependencies, no dynamic import, no eval/`new Function`, no code fetched at load. `Deno.Command` invokes only the local `ssh` binary. Clean.
6. Docs match code: argument table, defaults (22/15/85/8), method name and count (one, `discover`), all four resource kinds and every listed field, instance-name statement (hash suffix on alarms/mounts only, `node-<slug>` without), version string, example config, and every Security-section claim (userinfo rejection, BatchMode=yes, no local shell, error sanitization) verified against the source. No drift found.
7. Data written: enumerated below; the README's Security section discloses all of it, including the free-text `error` field and the injection caveat. No write can include a secret.

## Data written by this extension
- `node` — node name, configured URL (verbatim, userinfo-free), reachability, transport, Netdata version, agent hostname, OS name/version, core/collector/chart counts, alarm counts, Netdata Cloud claim status, sanitized error class. Hostname + OS + version is infrastructure-identifying inventory; disclosed in the README.
- `alarm` — node, alarm name, chart, status, value, units, and Netdata's free-text `info` (agent-supplied text, injectable over plain HTTP; disclosed).
- `mount` — node, mount path, capacity/usage figures, threshold flag. Mount paths are environment-identifying; disclosed.
- `summary` — fleet counts and sync timestamp only. No personal data.
