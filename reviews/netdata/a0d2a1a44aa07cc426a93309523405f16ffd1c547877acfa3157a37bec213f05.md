## Checked and clean
1. Secrets/identifying info — read every line of netdata.ts (code, comments, strings), README, manifest, LICENSE: no credentials, keys, tokens, PEM, cookies; no real hostnames, IPs, MACs, serials, emails, tenant IDs; examples use `example.com`/`netdata-reader`; `127.0.0.1` at README:69 is the loopback inherent to the ssh-transport design, not identifying; no secret-store paths; no local filesystem paths; no raw control bytes (U+001F written as `\u001f` escape at :189); comment :186 names the sibling public extension "truenas" only. 3. Transport — TLS verification cannot be disabled (fetch defaults; curl without `-k`); timeouts on every call (ssh ConnectTimeout :319, process abort :330, curl `--max-time` :311, fetch :368); vendor-hostname validation N/A (self-hosted agents). See findings 2, 3, 9, 10, 11.
4. Untrusted input — no HTML rendering; remote ssh command built only from validated inputs inside single quotes (url refined :34, host/user refined :53-58, timeoutSec integer); no SQL/file paths from API data; alarm/mount instance names hashed over raw identity with U+001F separator (:189-204). See findings 1, 4, 6, 13, 14.
5. Supply chain — single import, no dynamic `import()`, no `eval`/`new Function`, no load-time fetch; manifest `dependencies: []`. See finding 5.
6. Docs vs code — argument names/types/defaults, method name and args, resource names and field lists, instance-name hash caveat, and version string (README, manifest, `model.version` all `2026.08.22.2`) match. See findings 7, 8 (and 3/9 for the scheme claim).
7. Data written — enumerated below; no secret reaches a resource. See finding 7.

## Data written by this extension
- `node` (one per configured node): `name`, `url` (from config, trailing slashes stripped), `reachable`, `error` (free text: ssh `user@host`, ssh stderr excerpt ≤160 chars, HTTP error body excerpt ≤200 chars, or abort/timeout message), `transport`, `version`, `hostname` (the monitored machine's real hostname — identifying), `osName`, `osVersion`, `cores`, `collectors`, `charts`, `alarmsActive`, `alarmsCritical`, `alarmsWarning`, `claimedToCloud`, `mountsOverThreshold`; tags `reachable`, `os`, `alarmsCritical`.
- `alarm` (one per active alarm): `node`, `name`, `chart`, `status`, `value`, `units`, `info` (Netdata alarm description text); tags `node`, `status`.
- `mount` (one per `disk_space.*` chart): `node`, `mount` (filesystem path — may embed user names, e.g. `/Users/<name>` or `/home/<name>`), `availGiB`, `usedGiB`, `totalGiB`, `usedPercent`, `overThreshold`; tags `node`, `overThreshold`.
- `summary` (single): `nodes`, `nodesReachable`, `nodesUnreachable`, `alarmsActive`, `alarmsCritical`, `mountsOverThreshold`, `syncedAt`; tag `alarmsCritical`.
- Log lines (not resources): node name, url, ssh `user@host`, error strings, mount labels.
- Personal/sensitive: hostnames and mount paths (disclosed at README:94-95); `error` contents and `claimedToCloud` are not disclosed (finding 7). No credentials are written.
