## Checked and clean
1. **Secrets / identifying info** — Searched all four files for credentials, tokens, key material, PEM blocks, cookies, hostnames, device names, emails, account IDs, MACs, serials, non-vendor domains, IPs, secret-store paths, local filesystem paths, and raw control characters. None found. All examples use `example.com` / `netdata-reader`; `127.0.0.1` in the README example is the documented loopback-bind pattern for the ssh transport, not an identifier; `\u001f` is written as an escape, not a raw byte; the comment at `netdata.ts:196` references the sibling public `truenas` extension only. LICENSE author name: see finding 8.
2. **Credential handling** — The model takes no credential arguments (no token/password/key fields exist, so nothing needs `sensitive`); `url` rejects userinfo (`:37-38`) and the README says to use ssh for agents needing auth; no secrets in logs, errors, resources, or URLs; nothing written to disk. Persistence of non-secret ssh target + stderr into the resource: see finding 1.
3. **Transport / network** — TLS verification is never disabled and no option exists to disable it (no `-k` in the curl command, default Deno fetch); scheme restricted to http/https (`:37`), blocking `file:`/`data:`/`ftp:` for both fetch and remote curl; ssh uses `BatchMode=yes` (unknown host key fails closed), `ConnectTimeout`, argv (no local shell), host/user rejected if they start with `-`; every call has a timeout (`AbortSignal.timeout` on fetch, `--max-time` + `ConnectTimeout` + overall timeout on ssh); outer path rethrows on caller abort (`:499`). Vendor-hostname validation is N/A (self-hosted agents). Cleartext acceptance: finding 2. Redirect downgrade: finding 3. Inner-catch cancellation: finding 5.
4. **Untrusted input** — No HTML rendering; no SQL; no file paths built from input; the only command is the ssh remote string, whose interpolated `base` is validated to contain no `'` and `path` is internal with `'` stripped; `encodeURIComponent(chart)` on the data query; mount dimensions resolved by label and refused rather than guessed (`:456-468`); unreachable/degraded nodes carry forward last-known values and protect their records from prune; summary exposes `nodesDegraded`. Blind casts / non-object bodies: finding 6. Node-name slug collision and prefix over-protection: finding 4. Failed-mount count drift: finding 7.
5. **Supply chain** — Sole import is `npm:zod@4` (sanctioned bare major). No other npm/jsr/https imports, no dynamic `import()`, no `eval`/`new Function`, nothing fetched and executed at load. `Deno.Command("ssh")` runs the local system ssh binary only. Manifest `dependencies: []`.
6. **Docs vs code** — Arguments table (names, types, defaults, required) matches `NodeSchema`/`GlobalArgsSchema`; one method `discover` with optional `node` matches; all four resource field lists match `NodeStateSchema`/`AlarmSchema`/`MountSchema`/`SummarySchema`; instance-name hash statement matches `instanceName`; prune/single-node behaviour matches; version `2026.08.23.1` matches manifest and `model.version`; repository URL matches manifest. The SECURITY.md link target is outside the reviewed file set and was not verified. Security-section claim about `error` contents: finding 1.
7. **Data written** — See list below. README's Data written table discloses hostnames, OS, Netdata version, node URL, alarm names/values/info, mount paths and capacity, and cloud-claim status; it does not disclose that `error` can carry ssh `user@host`, ssh stderr, or HTTP response body text: finding 1.

## Data written by this extension
- `node` (one per configured node, name `node-<slug>`): `name`, `url` (operator-configured; may be an internal hostname/IP), `reachable`, `error` (free text — currently may include `ssh.user@ssh.host`, ssh stderr, HTTP status + up to 200 chars of response body), `transport`, `version`, `hostname` (the monitored machine's real hostname, from the agent), `osName`, `osVersion`, `cores`, `collectors`, `charts`, `alarmsActive`, `alarmsCritical`, `alarmsWarning`, `claimedToCloud`, `mountsOverThreshold`; tags `reachable`, `os`, `alarmsCritical`.
- `alarm` (one per active alarm, `alarm-<node>-<name>-<chart>-<hash>`): `node`, `name`, `chart`, `status`, `value`, `units`, `info` (free text from the agent); tags `node`, `status`.
- `mount` (one per `disk_space.*` chart, `mount-<node>-<mount>-<hash>`): `node`, `mount` (filesystem mount path on the monitored host), `availGiB`, `usedGiB`, `totalGiB`, `usedPercent`, `overThreshold`; tags `node`, `overThreshold`.
- `summary` (single record): `nodes`, `nodesReachable`, `nodesUnreachable`, `nodesDegraded`, `alarmsActive`, `alarmsCritical`, `mountsOverThreshold`, `syncedAt`; tags `alarmsCritical`, `nodesDegraded`.
- Personal/sensitive fields: machine hostnames, OS identity, mount paths, configured node URLs, and (per finding 1) ssh `user@host` / ssh stderr in `error`. No credentials, MACs, or user lists are written. Nothing is written outside the swamp datastore.
