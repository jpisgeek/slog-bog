## Checked and clean
1. Secrets/identifying info: read every string literal, comment, schema description, README line, example, and LICENSE. No credentials, tokens, PEM, cookies; no real hostnames/devices/domains (all `*.example.com`), no RFC 1918/public IPs (loopback → #9), no vault/secret-store paths, no `/Users`/`/home`/`/Volumes` paths, no raw control bytes (`"\u001f"` is an escape), no email/MAC/serial/tenant IDs. Comment at :196 references the sibling `truenas` extension in the same public repo — not private. Real name → #11.
2. Credential handling: no argument carries a secret, so nothing needs `sensitive`; `url` rejects userinfo and `'`; ssh uses the local agent/keys, never a password; nothing is written to disk or `.swamp/data` by the model. Persisted `error` content → #7.
3. Transport: TLS verification cannot be disabled on either path (no `-k`, no Deno TLS override); schemes limited to http/https; timeouts on every call (`AbortSignal.timeout`, `ConnectTimeout`, `--max-time`); outer cancellation handled. Cleartext → #2, redirects → #3, inner-catch cancellation → #4. Vendor-hostname validation N/A (self-hosted agent, operator-supplied URL).
4. Untrusted input: no HTML rendered; no local shell (`Deno.Command` argv array); remote command is single-quoted with `'` stripped from both URL and path, `encodeURIComponent` on chart names, `host`/`user` reject leading `-`, `port`/`timeoutSec` are ints; mount dimension resolution refuses to guess; alarm/mount names hash-suffixed. Blind casts and missing-key backfill → #5; node-name collision → #6; prefix protection → #8.
5. Supply chain: one import, no dynamic `import()`, no `eval`/`new Function`, no remote code at load. `Deno.Command("ssh")` resolves from PATH (expected). Pin → #1.
6. Documentation matches code: argument names/types/defaults, method name/count, resource names and every field list, hash-suffixed alarm/mount names, unreachable/degraded/prune behaviour, and the example config all match `netdata.ts` and the manifest; versions agree (README, manifest, `model.version`). Minor: README says `url` is persisted "verbatim" — code strips trailing `/` first. `error` content and HTTP-integrity caveat → #7, #2; host-key claim → #10.
7. Data written: see list below; README discloses hostname, OS, version, alarm names/values, mount paths, URL. Undisclosed `error` content → #7.

## Data written by this extension
- `node` (one per configured node, name `node-<slug>`): `name`, `url` (operator config, may include a query string if one was supplied), `reachable`, `error` (free text ≤200 chars: ssh `user@host`, local ssh stderr excerpt, remote HTTP error body excerpt — see #7), `transport`, `version`, `hostname` (real machine hostname of the monitored node — personal/device identifier, disclosed in README), `osName`, `osVersion`, `cores`, `collectors`, `charts`, `alarmsActive`, `alarmsCritical`, `alarmsWarning`, `claimedToCloud`, `mountsOverThreshold`; tags `reachable`, `os`, `alarmsCritical`.
- `alarm` (one per active alarm, hash-suffixed): `node`, `name`, `chart`, `status`, `value`, `units`, `info` (Netdata's free-text alarm description); tags `node`, `status`.
- `mount` (one per `disk_space.*` chart, hash-suffixed): `node`, `mount` (mount path — can reveal user/volume names such as `/Volumes/<name>` or `/home/<user>`; disclosed as "mount paths" in README), `availGiB`, `usedGiB`, `totalGiB`, `usedPercent`, `overThreshold`; tags `node`, `overThreshold`.
- `summary` (single record): counts only plus `syncedAt`; tags `alarmsCritical`, `nodesDegraded`.
- No secrets are written on any path; no field is marked sensitive and none needs to be.
