## Checked and clean
1. Secrets and identifying information: Checked every published file for embedded credentials, real infrastructure identifiers, private domains/IPs, local paths, secret-store names, and literal control characters; none found beyond the accepted publisher and repository identities.
2. Credential handling: Host and user are marked sensitive; no password, private key, token, or credential is accepted or persisted. See findings 4–5 for deliberate infrastructure-identity exposure.
3. Transport and network: SSH uses strict host-key checking, public-key-only authentication, disabled forwarding/proxy commands, bounded output, timeouts, and caller cancellation. See finding 6 for the documented cross-operation race.
4. Untrusted input: Schemas, PowerShell quoting, wildcard/control rejection, resource identity framing, and failure handling were checked; see findings 1–3.

6. Documentation matches code: Method, argument, resource, and example documentation were checked; see findings 2–3.
7. Data written: See findings 4–5; the README discloses the inventory fields and readable identifiers.

## Data written by this extension
- `vmHost`: reported hostname, processor and memory capacity, VM storage path, VM count, and switch count. Hostname and storage path identify infrastructure.
- `vm`: VM name, state, status, generation, CPU count, assigned memory, and uptime. The ID contains the configured target and VM name; the state is also tagged.
- `checkpoint`: VM name, checkpoint name/type/time, and parent checkpoint name. The ID and tag expose VM and checkpoint identity.
- `vmSwitch`: switch name and type. The ID exposes the configured target and switch name.
- No resource contains the SSH username, password, private key, token, or other credential material.
