## Checked and clean
1. Secrets/identifying info: scanned all string literals, comments, README prose, example config, and manifest. Only the vendor domain `api.anthropic.com`, the declared public repo URLs, and obviously-fake placeholders (`example-vault`, `ANTHROPIC_ADMIN_KEY`) appear; no keys, PEM blocks, IPs, local filesystem paths, hostnames, emails, or control characters found — real name in LICENSE, see finding 3.
2. Credential handling: `credential` is `.meta({ sensitive: true })`; the secret travels only in `x-api-key`/`authorization` headers, never in URLs or userinfo; every error path returns fixed strings from `message()` and never echoes server text, the credential, or response bodies; nothing writes the secret to resources or disk. Clean.
3. Transport: origin is hardcoded `https://api.anthropic.com` (no user-supplied URLs, no cleartext opt-out, no TLS-disable option); per-request `AbortSignal.timeout` exists; caller abort is rethrown, not misreported as timeout/remote failure — redirect policy, see finding 1.
4. Untrusted input: per-row fields are strictly validated (`integer()`, decimal/currency regexes) and any invalid row voids the whole dataset as `invalid-response` rather than backfilling zeros; the `page` cursor is URL-encoded via `URLSearchParams` so it cannot rewrite path or host; no HTML, shell, SQL, or file-path construction from API data; resource name is the fixed `organization-usage` — malformed-bucket edge, see finding 2.
5. Supply chain: the only import in both published sources is `npm:zod@4` (the sanctioned runtime-provided exception); no other npm/jsr/https imports, no dynamic `import()`, no `eval`/`new Function`, nothing fetched at load time. Clean.
6. Docs vs code: type name, version (`2026.08.25.1` consistent across manifest, model, README, and dashboard producer), argument names/defaults, single `collect` method, `snapshot` resource fields and 90d lifetime, platform-vs-enterprise request-count and OAuth restrictions, and the Security section's discard/no-persist claims all match the code — RFC 3339 and minor-units wording, see findings 4 and 5.
7. Data written: reviewed the snapshot schema and report output; personal-adjacent breakdown fields are disclosed in the README Security section. See list below.

## Data written by this extension
- `snapshot` resource (90-day lifetime): token usage totals and per-group breakdowns (workspace IDs, model names, Enterprise product names), cost totals and breakdowns (currency, amount strings, provider cost `description` line items), coverage window, refresh timestamp, and status/error-kind fields. No credentials. Workspace IDs and description strings can reveal internal workspace and workload names — disclosed in the README Security section.
- Report output (markdown + dashboard bundle v1 JSON): aggregate states, token/cost totals, and account kind derived from the snapshot; breakdown-bearing fields are declared in the bundle's `sensitivity.fields` (`workspaceId`, `model`, `product`, `description`). No secrets.
