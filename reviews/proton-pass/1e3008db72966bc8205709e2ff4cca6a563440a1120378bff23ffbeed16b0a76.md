## Checked and clean
1. Secrets and identifying information: reviewed all four published files; no credential, real vault/item name, private operator path/host/account, control character, or hidden infrastructure identifier was found. Public publisher/repository/vendor identity and synthetic placeholders are accepted.
2. Credential handling: secret values are read from strict named response locations, returned directly, and never interpolated into errors, stored, cached, written to disk, or logged by this provider. Raw CLI stdout/stderr and spawn causes are withheld from failures; configuration and locator strings are bounded and control-screened. See finding 3 for deliberate locator logging.
3. Transport and network: this extension opens no network connection itself; the selected official CLI owns Proton transport. Child execution has whole-call timeouts and caller cancellation through resolution, spawn, stream reads and post-await return checks. See finding 1 for the executable trust boundary.
4. Untrusted input: CLI argv uses fixed argument arrays and joined option values; relative executable/PATH entries are refused; stdout/stderr are capped; stdout requires strict UTF-8 and duplicate-key-safe JSON; recognized outer shapes are strict; identity, title, type, liveness and vault/share claims are compared when present; ambiguous titles/fields/values are refused; and malformed/missing values never become successful empty secrets. See finding 2 for optional claims.
5. Supply chain: only sanctioned runtime `npm:zod@4` is imported; no remote dependency, dynamic code, shell, eval, or fetched executable exists. The child environment is cleared and rebuilt from a bounded allowlist whose path/transport values are screened. See finding 1.
6. Documentation matches code: verified the read-only `get`/`list` provider contract, configuration, title/field grammar, removed URI/write surfaces, binary resolution, environment, bounds/cancellation, item-list/view validation, ambiguity rules, optional claim limits, data handling and diagnostic disclosure. See findings 1-3.
7. Data written: none. The provider returns the requested secret or live item-title listing to its caller and writes no resource, cache, file or Swamp datastore entry.

## Data written by this extension
- No resources or persistent data are written by this extension.
- `get()` returns one live secret value to the requesting caller; `list()` returns live, addressable item titles. Those return values remain sensitive even though this provider does not persist them.
