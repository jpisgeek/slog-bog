## Checked and clean
1. Secrets/identifying info: swept all five files' code, comments, string literals, README prose, and examples — only `api.openai.com` (vendor API) and the intentionally public `github.com/jpisgeek/slog-bog` links appear; no credentials, tokens, IPs, local filesystem paths, real hostnames/devices, emails, or control characters; example placeholders (`example-vault`, `OPENAI_ADMIN_KEY`, `EXAMPLE_UNIX_SECONDS`) are obviously fake — except the LICENSE name, see finding 2.
2. Credential handling: `apiKey` is `.meta({ sensitive: true })` (openai_usage.ts:5); used only in the Authorization header (line 140); never in URLs, logs, resource data, tags, instance names, or thrown errors; all persisted error text comes from the fixed-string `safeMessage` table (lines 106–117), never server bodies; no URL userinfo; nothing writes a secret to disk — clean.
3. Transport: single hard-coded `https://api.openai.com` origin with no configurable host, no cleartext opt-out, and no TLS-disable option; per-request `AbortSignal.timeout(g.timeoutMs)` on every call; caller abort is rethrown (line 191, `if (callerSignal.aborted) throw`), never misreported as timeout/remote failure; no user-supplied URLs exist — clean.
4. Untrusted input: page envelope, usage rows, and cost rows are field-checked with strict type/range/regex tests; any invalid record nulls the whole dimension and records `invalid-response` (absent is never backfilled as zero); duplicate-cursor and missing-cursor loops terminate as `partial`; no HTML, shell, SQL, or path construction from API data; single fixed resource instance name (`organization-usage`) so no collisions; unavailable/partial states propagate to the dashboard rather than reading as healthy — clean except the severity-fidelity issue in finding 1.
5. Supply chain: the only import in both source files is `npm:zod@4`, the sanctioned runtime-provided specifier; no other npm/jsr/https imports, no dynamic `import()`, no eval/`new Function`, nothing fetched at load time — clean.
6. Docs vs code: argument names/types/defaults, the single `collect` method and its arguments, resource name/lifetime/fields, report name, model type, and version `2026.08.25.1` all match across README, manifest, model, and report; README security claims (sensitive marking, header-only use, no persistence of bodies/error text, fixed HTTPS origin, breakdown-name exposure) verified true against the code — clean.
7. Data written: enumerated below; workload-name exposure via breakdown identifiers is explicitly disclosed in README Caveats and Security — clean.
