# Compositions

## Fleet health

Start with one declared system. Add Mac Mini, Mac Studio and Mac Air as neutral
inventory labels, with one fixed probe per approved target. Inspect OS versions,
uptime, memory headroom, load and startup-data free space. A key failure is an
access gap, not a claim that a machine is offline. Fixed-probe SSH keys and a
named refresh workflow make read-only household dashboards possible without
handing the browser administrative access.

A hypothetical fleet using those product labels can combine collection,
stale-data handling, restricted-key checks and versioned reports. Test complete
navigation and refresh routes before enabling a recurring workflow. These are
generic composition examples; connections, credentials, grants, schedules and
hosting belong to the operator's deployment.

## Quest season report

A Quest workflow can combine these fleet checks with public leaderboard evidence
and use the separately published `@jpisgeek/dashboard-report-view` for the score
report. Set `view.questPath` only when your host actually serves that report.
This package does not fetch scores, promise points, infer a season cutoff or
start Quest schedules. Keep ranks, observed scores and individual-run award
attribution separate; a successful workflow alone does not establish points
awarded.

## Rebuild preparation

Versioned observations help compare an OS version or available capacity before
and after an attended rebuild. Keep source and report evidence portable, and
record intentional exclusions through `coverageNotes`. Observations do not prove
backup completeness, restore success or permission to erase a system. A rebuilt
host needs its public automation key reauthorized and its new host key verified
through your approved setup process.
